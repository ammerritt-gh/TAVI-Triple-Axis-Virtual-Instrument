# Changelog

Fragments for the next release live in `changelog.d`; see `changelog.d\README.md` for the format.

## v1.4.1 — 2026-10-20

**Read this first.** 1.4.1 is a bug-fix release that restores higher-order (harmonic) reflections on PANDA and IN12. From v1.3.0 through v1.4.0 both instruments reflected first order only at the monochromator and analyzer, so their simulated scans from those versions lack the higher-order contamination a real triple-axis measurement carries; rerun any PANDA or IN12 result where that matters. The filters, guides and velocity selector that suppress this contamination on the real instruments are not modelled, so the simulated contamination is larger than the real instruments'. PUMA and IN8 are unaffected.

### Bug fixes

- From v1.3.0 through v1.4.0, PANDA and IN12 reflected first order only at both crystals, so their simulated results on those versions lack higher-order (harmonic) contamination. Version 1.4.1 restores it, as PUMA and IN8 always had; the filters, guides and velocity selector that reduce that contamination on the real instruments are not modelled, so the simulated contamination is larger than the real instrument's.

## v1.4.0 — 2026-10-19

**Read this first.** 1.4.0 brings several major changes:
- Improved installer and launcher options and reliability
- Redone GUI windows for better use of space, adaptable to large or small monitors
- Rewrote how angles are handled to better match ILL (A1-A6) conventions and clear up secondary angle names
- Fixes for the UB matrix calculations and alignment
- Improved direct-sampling Maxwellian source and include facility source profiles
- Better handling of various elements like incompatible scan commands, stopping in-progress scans and special characters in folder names

### Major features

- The window now fills the screen and arranges its panels for it: View, Layout offers 2, 3 or 4 columns (3 on a large screen, 1920x1080 at 100 % included; 2 on a laptop or at 125 %), View, Column Width makes the form panels one or two blocks wide, labels sit beside their values, and the rarely changed Instrument blocks (crystal focusing, modules, source) start folded with a line saying what they hold. Save Parameters, Load Parameters and Load Defaults moved to the File menu and Clear Runtime Data to the Config menu, where it now clears the current instrument only; the first start after updating sets the previous window layout aside and uses the new one.
- The sample's hidden mount is now the only thing a training exercise hides: the psi and kappa corrections, the motor-zero errors and the Misalignment panel are removed everywhere, including the scan commands, the API and the saved settings. A scan of omega now turns the sample table (A3) itself, and an angle scan beside a Q, HKL or energy-transfer scan is refused, even with force, because one command would silently scan the other's quantity; so is any pair of commands that write one scan slot (the same variable twice, A3 with omega, A4 with 2theta). A new training exercise is made only when its peaks can be reached within the instrument's motor travel, and a code from an older version, or a settings file saved by one, is refused with a message saying why instead of being half-loaded; the refused settings file is kept beside the original as a backup. A settings file that is not readable JSON, such as a truncated one, is set aside the same way instead of stopping TAVI from starting. A loaded training exercise that the sample, fixed energy or crystals in use cannot observe stops the settings from being saved, with a message: the last consistent file stays on disk, and restoring those settings or clearing the exercise lets saving resume. A sample with no Bragg reflections, such as the phonon-only Al samples, offers no training exercise, and generation says why.
- All four instruments now start neutrons from the moderator they really view, sampled directly: PUMA the FRM2 thermal source, PANDA the FRM2 cold source, IN8 the ILL thermal tube and IN12 the ILL cold source. The spectrum is the true flux form of up to three Maxwellians, so the second-order intensity that the old source overstated is now right, and it no longer follows the scan: changing kf or Ei never changes what the source emits. The Source Control block has a mode (full spectrum, or an unphysical flat band of half-width dE about Ei for quick statistics), a list of published facility fits, six editable temperature and flux fields that mark the entry as modified when you change one, and a preview plot of the spectrum with Ei and 4 times Ei marked. PANDA can be switched to a thermal source with one pick. Absolute intensities between instruments are not calibrated yet, and guides are not modelled, so the full spectrum overstates the higher-order contamination of IN12 and, less so, PANDA. Over the API the old source type and dE fields are refused with a message naming the new fields, and a settings file that still holds them has them ignored, with a line in the message log saying the instrument's default source was applied. Every saved scan now records the source mode, the temperatures and fluxes, and the facility entry they started from.
- TAVI's angles are now numbered the way the ILL numbers them, with physical names in the panels: A2 is the monochromator take-off, A3 the sample rotation, A4 the sample 2θ and A6 the analyzer, and the two Bragg angles A1 and A5 show as read-only values beside their 2θ fields. Scripts that drive TAVI over the remote API must declare the new API version and use the new names (an old script is refused, never silently reinterpreted), and a settings file or a scan folder saved by an earlier TAVI is refused with a message, the settings file being set aside as a backup. Scan commands with a zero step, a step whose sign runs away from the end, or a step longer than the range are now refused in the GUI and over the API instead of being accepted.
- Two scan commands that cannot both be honoured are refused before anything runs, in the Run dialog, on the scan-command box and over the API. The refusal names what owns each quantity, for example "A4 (sample 2θ) is calculated from H in the HKL calculation, so it cannot also be scanned." Force no longer clears these; it still clears the warnings for a one-point scan and for one over 1000 points. A slit gap can now be scanned, in millimetres, on all four instruments but not on the analytic engine. A scan that selects no geometry, such as a plain Run, a curvature scan or a slit scan, holds the motors where the panels show them instead of re-solving them from H, K and L (an API request that patches H, K or L solves the motors from them first). A scan that reads an empty field refuses the Run and names the field. Relative scans preview, run and reload on their absolute values, and a relative radius range that leaves the bender's travel is refused at launch. On PUMA the velocity selector follows the incident energy in direct-motor scans. McStas parameter names are now physical (mono_two_theta_param and so on, with the new mono_theta_param and analyzer_theta_param), and they show in the detector.dat headers. Under a plane lock a direct-motor point runs at the lock's tilts. A step that does not divide the range now stops at the last point inside it, with a warning, instead of running past the end. A curvature scan whose range crosses zero is refused, since a radius is a magnitude and it would repeat bends, and an API request that names a crystal 2θ and a different energy for the same side is refused.

### Minor features

- TAVI now keeps a crash log, output/tavi-crash.log; please attach it when you report a crash. Each launch adds a line naming the operating system, the Python, PySide6 and matplotlib versions, and the display session, followed by anything that goes wrong: uncaught errors from the panels, plots and scan threads, Qt's own warnings, and on Linux and macOS the Python stack of every thread on a hard crash. The console prints the file's path at startup; one session writes at most 1 MB, and the next launch starts a fresh file once it is past that size.
- Each field a scan steps carries a dashed outline in its command's colour and a 1 or 2 badge; a relative step shows 1 +Δ or 2 +Δ, and hovering it shows the base value and the absolute range. A field the run sets at every point has a darker outline, badged with the command or commands that drive it, or with the setting that holds it, such as fixed Kf, fixed Ki or plane lock. A field the run will set from other typed values is marked with its source, for example from A2, when it shows a different value from the one the run will use. A group the scan does not read, such as HKL during an angle scan, says it is not used by this scan. The marks follow the next Run and never block anything: nothing is greyed or locked. While a command is half-typed, or two commands cannot be honoured together, the set-per-point marks are withdrawn, and a command that is valid on its own keeps its scanned mark. Goto CEN now works after a scan of the analyzer vertical radius. A scan of more than 100,000 points is refused in the GUI and over the API, before any of its points are built, and no flag clears that refusal.
- In the Fitting dock, the Area row is replaced by three intensity rows: Integrated (counts, which depends on the step, the one to read against the plot), Normalised (counts times the scan unit, the same whatever the step, and the value the Area row showed) and Raw range (counts over the fit range, with no peak shape assumed). Each position has its own Go button, the groups sit side by side in a wide dock, Copy results copies the whole fit as a table, and the fit curve stays on the plot when the scan's axes are redrawn mid-scan.
- Each of the four radii (rhm, rvm, rha, rva) has a Track ideal box that is never greyed out while the radius tracks: ticking it puts the calculated ideal into the field and keeps it following the angles and every scan point, and unticking it, or typing a value, holds the radius. A row that is not tracking says why in a line under it: held with its distance from the ideal in metres, scanned by a numbered command, fixed by the instrument, or no focusing model for the analyzer. A help line under the rows says what a scan does with each. Folded, the block shows its four radii as a two by two with each value and mode, and a flag on its header counts the radii that are held, scanned or without a model. A fresh start and File, Defaults now tick every radius that can track, where they used to hold all four; saved parameters keep their choice, and a file that does not record it loads ticked.
- The Windows installer is now WINDOWS-install-TAVI-v1.4.0.bat. It runs one small simulation through TAVI itself and ends on INSTALLATION SUCCEEDED, INSTALLATION FAILED or TAVI INSTALLED, BUT THE TEST SIMULATION FAILED. It also offers a desktop copy of the TAVI Launcher shortcut. The launcher menu has a new item 5, Collect diagnostics for support, which zips the logs, the crash log and the TAVI Doctor's report. Exit is now the last item. The installer and launchers keep a log of each run in %LOCALAPPDATA%\TAVI\logs.
- Scan folders can now be named with umlauts, ß, French accents and spaces, and the scan runs in them; TAVI hands McStas the Windows short name of the folder, and the names TAVI shows and saves keep exactly what was typed. On a drive without short names (where Windows gives none), a folder McStas cannot use is refused when Run is pressed, before anything is simulated: the message names the folder, says what the problem is, and says to rename it or, on another drive, to choose a folder on C:. A folder name containing &, ^ or % is refused at Run on any drive.
- PANDA's diagnostic options now include PUMA's monitor suite: 21 monitors from the source to the detector, each switched on in the Diagnostic Options Configuration dialog. A new experimental velocity selector can be switched on from the instrument panel. It is off by default, is not a real PANDA part, and passes only 40 mm of the 138 mm guide-exit height, so about 70% of the beam height is clipped there.
- Stop Simulation finishes the current point and then ends the scan, and the button then reads Force stop; clicking it ends the McStas processes of the point in flight at once and discards that point, so a partial count is never recorded as a measurement. The same two steps apply to the Cancel button in the API dock, and a script can force-stop over the API with a kill field on both stop requests, which then reports how the scan was stopped. Long scans on the analytic engine no longer lock up the window: the plot, progress bar, counts and log update a few times a second instead of once per point, and the Stop click is handled promptly. Closing the window while a scan is running or queued now asks first (Keep running is the default). Switching instrument keeps its Yes/No question (No is the default), and a Yes stops the scan completely before TAVI restarts.
- The Diagnostic Options Configuration dialog now has a choice that makes the energy monitors record wavelength instead of energy. Their plots then show wavelength in Å, their output files and plot titles say `Lmonitor` instead of `Emonitor` (e.g. `source_Lmonitor`), and the change applies on the next diagnostic run.

### Quality of life

- Collimator choices now read Open where no collimator is installed, instead of 0, in the Instrument panel and in the plot's info text, where the other collimators now carry their arcminute mark; hovering explains Open. Saved settings and scripts are unaffected.

### Bug fixes

- Changing a monochromator or analyzer angle, or an energy that moves one, now moves Q, HKL and the energy transfer to follow the motors, in the panels and over the remote API, and a monochromator or analyzer angle of zero now launches with no selected energy recorded instead of being refused, while in the panels it leaves the energies and the position as they were, marked stale, instead of showing a zero energy. A remote update naming a position together with a sample stage motor is refused before anything changes, values sent together in one update no longer overwrite one another, slit gaps must be finite and not negative, fine scans keep their step precision instead of collapsing to three decimals, a remote update naming a position or an energy transfer beside a monochromator or analyzer angle of zero is refused, and Save writes the peaks shown in the UB Matrix panel even before a UB is calculated, refusing while a peak field is not a number.
- Release 1.3.2 said that an old saved session's or scan folder's χ loads as sgl. It does not: χ is refused, and the sample's tilt arcs are sgl and sgu.

## v1.3.2 — 2026-10-07

**Read this first.** Release 1.3.2 rebuilds how TAVI orients a crystal: the sample sits on a turntable carrying two tilt arcs, sgl and sgu, which replace χ, and the simulated crystal follows its true mount rather than your UB matrix, so a wrong UB misses its peaks as it would on a real instrument. Calculate UB is fixed on IN8, IN12 and PANDA, where it came out turned 180°. The Windows installer keeps everything in one folder you choose, adds Uninstall to the launcher menu, and always starts the Python and McStas of its own installation. Each simulation point now runs 4 MPI processes by default on every platform, set under Config → MPI processes.

### Major features

- The simulated crystal now sits where the sample really is, not where your UB matrix says, so a wrong UB misses its peaks as on a real instrument; you can describe how the crystal is mounted with an optional mounting plane in the Sample dock, and training in both the UB Matrix and the Misalignment docks is graded by the worst miss over your reflections, with the Misalignment dock's tolerances now 0.5° and 2°. A new Lock plane in the UB Matrix dock holds the tilt arcs and kappa for an experiment: every point is solved at the locked tilts, a point out of the plane is refused naming the plane, and a STALE mark shows when your UB no longer levels it.

### Minor features

- The Windows installer asks where to put TAVI and keeps the program, its Python environment, McStas and the downloaded packages together in the folder you name, then opens that folder when it finishes. A shortcut is left inside it that you can move wherever you like, such as your desktop.
- After Calculate UB the UB Matrix dock shows how far each peak sits from your UB and whether each pair of peaks is at the angle its indices imply, so a mis-indexed peak is flagged, and Refine Lattice now respects the crystal system. The scattering-plane panel names the zone axis, the c* elevation and the a* azimuth, selecting a sample moves your UB onto its lattice, training grades reflections that lie in your mount's plane, and a locked plane runs at exactly its kappa from the GUI as from the API.
- The instrument dock shows both sample goniometer arcs, sgl and sgu: they are solved from Q and HKL, can be typed in and scanned in angle mode, and a saved session's or old scan folder's χ loads as sgl. Take Position now records the whole stage with the ψ and κ corrections in force, so changing a correction later does not move a recorded peak; older peaks are marked legacy and fit as before.
- The launcher menu now has an Uninstall option, so removing TAVI no longer means finding the uninstaller you downloaded months ago. It lists exactly what will be deleted, including your saved scan results, asks again if there are any, and leaves anything else you have put in the folder where it is.

### Quality of life

- The Windows installer no longer needs Visual Studio or the Microsoft MPI SDK. The C compiler is installed together with everything else, and the installer compiles and runs a test instrument before it finishes so a broken compiler is caught at install time, not at your first scan.
- The macOS and Linux installer, attached beside the Windows one, now compiles and runs a small test instrument with two MPI processes before it finishes, so a broken compiler or MPI setup stops the install instead of the first scan. The script is provisional and has not yet been run on either platform.
- A double-click support recorder collects a failed Monte Carlo run, its frozen instrument settings and diagnostic logs for offline troubleshooting, including failures before the application opens.

### Bug fixes

- The installer no longer stops with "Cannot uninstall shiboken6" or starts TAVI with a Qt DLL error afterwards. Every Python package now comes from the same conda-forge channel, an existing environment is rebuilt instead of patched, and the installer checks that the GUI toolkit loads before it finishes.
- Starting TAVI now always uses the Python and McStas that belong to that installation. Where a machine carried a second installation under the same name, a normal start could take the program from one and the simulation engine from the other, and every neutron simulation then failed while the analytic engine carried on working. A separate repair tool fixes machines already installed with an earlier version, without reinstalling.
- The number of MPI processes per point is now a setting in the new Config menu, remembered on this computer, and starts at 4 on every platform instead of a fixed 30, which Open MPI refused on small Linux and macOS machines.
- Out-of-plane Q and HKL points are now reached the way a real sample stage reaches them: a turntable carrying two crossed arcs, with the arcs' travel enforced where a source documents it (PUMA and IN12 ±20°, PANDA ±15°; IN8 unlimited) and a refusal naming the arc, the angle it needs and its travel when a point is out of reach. The simulation no longer mounts the crystal with the inverse rotation: until now a crystal oriented 23° one way was simulated 23° the other way.
- Calculate UB now gives the right crystal orientation on IN8, IN12 and PANDA, where it came out turned 180° and sent HKL moves after a fit to the wrong setting (PUMA was not affected). Saved peaks load unchanged and fit correctly, and a UB matrix saved before this fix loads as it was saved: on IN8, IN12 and PANDA the message center says it may still be turned and Calculate UB refits it.

## v1.3.0 — 2026-09-14

**Read this first.** Release 1.3 adds a fast analytic scan engine that returns an approximate result in milliseconds per point, for a quick check before committing to the full neutron simulation. IN12 (ILL) and PANDA (MLZ) join PUMA and IN8 as selectable instruments, each with a model-status document recording what is verified and what remains approximated. A reciprocal-space panel draws the scattering triangle, the lattice points and the instrument's reachable region for the current sample and settings, updating as you change them. TAVI can now be driven from outside the window through a local API server, with an API panel in the GUI and a user guide describing every request.

### Major features

- Scans can now run on a fast analytic engine instead of the full neutron simulation, giving a fast approximate result for the supported sample models in milliseconds per point instead of seconds to minutes. Use it for a quick check before committing to the real simulation, not as a substitute for it.
- IN12 (ILL) and PANDA (MLZ) join PUMA and IN8 as selectable instruments, PANDA in its documented pre-shutdown configuration; each instrument's model-status document records what is verified and what remains approximated.
- A reciprocal-space panel draws the scattering triangle, the lattice points and the instrument's reachable region for the current sample and settings, and updates as you change them, in the style of vTAS.
- TAVI can now be driven from outside the window: a local API server accepts scan, validation and instrument requests from scripts or other programs, with an API panel in the GUI to start it and watch it, and a user guide describing every request.

### Minor features

- The sample loaded for a scan can now be chosen as part of a remote API request, the same way it is chosen in the GUI.
- A standalone dispersion viewer window plots the phonon dispersion of any sample that has a dispersion map, such as the new lead sample, along a chosen crystal direction, with an optional comparison overlay, without running a scan.
- A Fitting dock fits a peak in your scan data and moves a motor to its centre, maximum or centre-of-mass position, with one click to undo the move.
- A lead sample with a three-branch phonon dispersion from a DFT calculation by Rolf Heid (KIT) is available in the sample library alongside the simplified samples. Its dispersion map is generated on your machine by the installer (or by hand with `tools\make_pb_assets.py`); until then the sample is listed but a run with it fails to load.
- Each bending direction of a crystal can now be set independently to auto-focus, held at a fixed radius, or driven by a scan, and the analyser's second focusing axis is a real setting rather than a hidden fixed value.
- A Resolution calculator under the Utilities menu shows the instrument's theoretical momentum and energy resolution at any reciprocal-lattice point and energy transfer you type in, without running a scan.
- A scan-time benchmark under the Utilities menu measures your computer's simulation speed and uses it for more accurate time estimates before you launch a scan, shown as overhead and neutron rate.
- A configurable synthetic nuisance background, with environment, instrument and sample contributions, can be added on top of the simulated counts from a new dialog; it is a plausible background, not a prediction of a real facility's. It is off by default, so existing scans look exactly as before until you turn it on.
- IN8 gains the collimator slot between source and monochromator that ILL documents, alongside the three slots it already had; it is open by default, so existing IN8 settings run as before.

### Quality of life

- A scan request too large for the configured neutron budget is turned down immediately, rather than after the program has worked out which of its points are reachable.
- Simulations that use a phonon dispersion sample start noticeably faster: the dispersion data loads in a few seconds instead of up to half a minute.
- You can request more neutrons per point and per queued job than before, for scans that need extra statistics.

### Bug fixes

- An API scan or validation request with a mistyped or misplaced setting is refused immediately with a message naming the field, instead of being accepted and silently doing something unintended.
- Submitting a scan or validation request through the remote API no longer depends on whatever is sitting in the GUI's scan boxes, and a scan already queued or running is no longer affected by later changes in the GUI.
- Values TAVI writes into the number boxes itself, after a goto-CEN, a remote API write or a derived recalculation, no longer show up highlighted as unconfirmed edits. Only values you typed and have not yet applied are highlighted.
- Editing an energy or wavevector now moves the monochromator and analyser onto the branch the selected instrument actually uses, and a scan submitted through the API or started from fresh defaults on IN8, IN12 or PANDA is no longer refused or driven on the wrong side.
- Scanning a crystal's angle through its zero-degree position no longer crashes the run. At that position an auto-focused crystal is treated as unbent, as if pointed straight at the beam with no focusing; a radius you hold yourself stays as you set it.
- A scan that passes through an instrument's direct-beam position (a crystal at exactly zero degrees) no longer crashes or shows a made-up energy transfer for that point. The point is marked as direct transmission and the values that cannot be known are left blank.
- An analyser focusing axis that the crystal's design permanently fixes (such as the vertical focus on PANDA or IN12) is now refused if you try to scan it, instead of silently letting the scan override it.
- Asking for an energy transfer larger than the neutron beam can supply is refused with a clear message instead of silently running a scan with invalid motor angles.
- IN8's monochromator angle range now matches the range ILL currently publishes, which is narrower at both ends than before (11 to 90 degrees instead of -40 to 110).
- Entering or sending an invalid number, such as infinite or not-a-number, for a crystal's bending radius is refused with a clear error instead of being accepted and producing a broken simulation.
- Choosing an option for an instrument's optional module (such as a beam-focusing mirror) that is not one of the supported choices is now rejected instead of silently building an instrument that does not match what you asked for. Changing only some module options over the API no longer crashes the run.
- The default neutron source now samples the Maxwellian spectrum it documents: its energy distribution was too cold, peaking as intended but with too few neutrons above the peak. Every instrument is affected, and counts at a given setting are lower than in 1.2 (about a quarter lower in the IN8 reference scan), so intensities from the two versions are not directly comparable.
- IN8's Cu(200) monochromator now carries its documented anisotropic mosaic (25 arcminutes horizontal, 10 vertical) instead of a single 25 arcminute value, which changes its vertical resolution and throughput.
- Opening a collimator to its widest, unrestricted setting now genuinely removes it from the beam path, instead of leaving its housing in place to absorb some neutrons.
- Updating one of an instrument's collimation settings over the API no longer clears every other collimation slot you did not mention.
- Starting a run after changing only some of an instrument's beam-defining slits no longer fails; the slits you did not touch keep their default values.
- A scan's recorded incident and final energies now always match the crystal angles the instrument used for that point, whichever energy you chose to fix.
- Typing a scan only into the second scan-command box now shows the correct number of points in the preview, matching what actually runs, instead of zero.
- Setting two bending radii of the monochromator in the same request no longer silently loses one of the values, whichever order you send them in.
