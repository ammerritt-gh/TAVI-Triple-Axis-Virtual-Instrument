## Organisation

**A test harness that was exactly what this session needed was sitting in a
gitignored directory, and finding it was luck.** The Monte Carlo acceptance
required building TAVI's own PUMA instrument and running one point — the thing
the installer's `PSI_DMC` compile gate explicitly does not cover. Writing that
from the plugin API would have taken a while: `compute_scan_snapshot` wants an
eleven-element scan tuple whose meaning is not documented at the call site. A
previous session had already solved it, in
`output/install-diagnosis/test_gcc.py` (45 lines), which builds PUMA through
`tests/test_puma_build_tree.py::_build`, sets the runtime parameters that
construction alone leaves empty, and asserts a `detector.dat`. `output/` is
gitignored, so that file is invisible to a fresh clone and to any search of the
tracked tree; I found it only because the spaced-profile handoff mentioned a
"GCC validation command" in passing and I went looking. Latent, still open. A
real-run harness that a later session will want again does not survive in
`output/`.

**The repository still carries an unmaintained installer that has the defect
this release exists to fix.** `installer/WINDOWS-install-TAVI.bat` (347 lines,
unversioned, tracks `main`) still generates launchers that run
`micromamba run -n tavi`. The design document's release recipe already says so —
"(e) `WINDOWS-install-TAVI.bat`, the unversioned copy that tracks `main`, is
unmaintained: it lacks the 1.3 changes and each release derives from the
previous *pinned* file. Delete it or bring it up to date before pointing anyone
at it." It is still there, and now it is the only installer in the tree that
selects an environment by name apart from the deliberately retained v1.1.0,
v1.2.0 and v1.3.0 pinned files. Latent; not fixed, because deleting it was
outside this slice. The new `tests/test_installer_launchers.py` excludes it and
the three pinned predecessors from its "no named selection" table, which is
correct but means nothing now flags it.

## Operator and agent surface

**`conftest.py`'s no-window guarantee has a hole that AGENTS.md's wording hides,
and it cost this session two operator interruptions.** AGENTS.md says the
repo-root `conftest.py` "on Windows, forces `CREATE_NO_WINDOW` on every
subprocess the session starts -- **do not remove or bypass it**", and the
conftest's own docstring says the same. Both are literally true and both read as
a blanket guarantee. They are not: the flag is applied to processes the pytest
session creates, and a process that *cmd* detaches with `start` is created by
cmd, not by the session, so it gets its own console window. My uninstaller used
`start` by design — a detached copy is what makes deleting the tree possible —
so every test run and every manual exercise of that path put a blank console
window on the operator's screen. He interrupted twice, the second time to say he
would cut the work off. Bit this session; the code side is fixed (the hand-off
now `cd`s out of the tree and `call`s the copy in the console already open, and
a test fails if `start` reappears in any shipped install/uninstall script), but
the documentation still promises more than it delivers. The smallest edit:
AGENTS.md's Verification bullet 3 and the conftest docstring should say the flag
covers processes the session creates and cannot reach one that cmd detaches.

**Driving the installer from a test needs a fact that is written nowhere:
`set /p` drains a redirected stdin, so a `choice` after it gets nothing and
returns 255.** The first attempt at an unattended cold install piped two lines —
the install folder, then `Y` — and died at the confirmation with "ERROR: The
file is either empty or does not contain the valid choices". Cost one aborted
run, about two minutes (measured), plus the design of a `/dir <path>` switch so
the folder answer never comes from stdin. Bit this session; the switch is in
`installer/WINDOWS-install-TAVI-v1.3.1.bat` and documented in the handoff, but
the underlying cmd behaviour is worth recording wherever the repo tells a future
session how to exercise a batch script.

**An environment trap on this machine, not in the trap list.** There is a stray
`copy.py` in `%TEMP%`. Python puts a script's own directory first on `sys.path`,
so any Python script run from `%TEMP%` has its `import copy` shadowed by it. The
v1.3.0 installer runs two generated helper scripts from `%TEMP%`, and on the
cold install this broke `mcstasscript`'s own `import copy` — McStasScript's
paths were then never configured, silently, because that step had no
`errorlevel` check. It took reading a traceback buried in a 137 KB install log
to see it. Bit this session. The installer side is fixed (helpers now run from a
folder the installer owns, and the step checks `errorlevel`), but the stray file
is still on the operator's machine and will shadow the standard library for
anything else run from `%TEMP%`. AGENTS.md already has an "Environment traps"
paragraph; this belongs in it.

## Agent instructions

**AGENTS.md's dependency-hub warning does not distinguish the surfaces that
matter.** It says "TAVI is a dependency hub — sweep consumers before moving or
renaming anything they touch", and names three: ISAR vendoring `geometry/` and
driving the REST API, and `MCPs\TAS_MCP` importing the `tavi` package. This
session rearranged the entire *installed* Windows layout — where the environment
lives, what it is called, where `INSTALL_INFO.txt` sits — and touched none of
those three surfaces. Working that out took a grep and a judgement call. One
clause distinguishing the installed layout from the package, `geometry/` and the
API surface would have made it a five-second check instead. Latent, minor, not
fixed.

Otherwise the instructions held. The "Before You Touch X" table pointed at the
right files; the McStas-parameter and threading-boundary rules were not in scope
but were accurate where they touched this work; the Verification section's
insistence on running one suite at a time, and on `-ra` so skips are printed,
was correct and useful (the single skip is `test_dispersion_map.py`, which needs
the gitignored `components/Pb_dft_phonons.dat`, exactly as documented).
